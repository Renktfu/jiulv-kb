# 收录约定

库不要求你的资料整理得多整齐，但目录名和正文里的几个固定字段，会直接决定检索与组稿准不准。这份文档说明它认什么。

## 目录与类型

收录时先看目录（不看文件名，文件名里的「选房」「亲子」是内容词，容易误判），命中即定类型：

- `13_钩子库` 或名字里带「钩子库」→ `hook`
- `04_风格规则与范文`、`规则总库`、`写作规则`、`风格规则` → `rule`
- `03_爆款精选索引`、`精选索引` → `index`
- `07_硬资料`、`政策`、`官方` → `fact`
- `05_代运营`、`代运营`、`提案`、`报价`、`合同` → `ops`
- `06_每日采集产出` → `daily`
- `room-types`、`roomtypes`、`选房`、`房型` 作为目录名 → `guide`
- `02_地区素材库`、`素材库`、`viral_posts`、`material_export` → `note`

目录没命中就看正文：出现「钩子」且出现「机制」判为钩子，出现「规则」且出现「必须」或「禁止」判为规则。都不中就是 `misc`。

类型会影响检索权重：`index` 降到 0.4（那种文件列几百个标题，容易把相关性带偏），`daily` 0.7，`ops` 和 `misc` 0.85，其余 1.0。S 级和 A 级分别再乘 1.25 和 1.12。

## 地区

先从路径和正文里数关键词，命中最多的胜出。认的地区：海南、云贵川、西安、长白山、新疆、崇礼、东南亚、上海、北京、广深。要加新地区改 `jiulv/extract.py` 里的 `REGION_KEYWORDS` 就行。

正文里如果写了 `- **地区**：海南·三亚·文华东方`，这个字段优先，第一段作为地区，第三段作为酒店名。

## 字段抽取

下面这些行会被抽成结构化字段，写在正文开头六行以内最稳：

```
- **标题**：三亚文华东方最全选房指南
- **作者**：波波de酒店日记
- **发布时间**：09-10
- **互动数据**：839赞 / 1131收藏 / 33评论
- **地区**：海南·三亚·文华东方（大东海/珊瑚湾）
- **链接**：https://www.xiaohongshu.com/explore/xxx
```

宽松匹配：`标题`／`标题：`、`- 标题:`、`**标题**：` 都认，冒号中英文都认。互动数据支持 `1.2万赞`、`146 评论，13 赞 66 收藏`、`839赞 / 1131收藏` 几种写法，`赞`、`点赞`、`收藏`、`藏`、`评论`、`评`、`阅读`、`播放`、`转发` 都识别。

爆款等级：正文里写 `爆款等级：S级`，或文件名以 `S_`／`A_`／`B_` 开头，都会记下来。

## 钩子的七字段

钩子库是这套东西里复用价值最高的部分，建议严格按格式写：

```markdown
## H-R-001
- 原文：带娃别订亲子房。亲子房是营销概念，你要的是双床
- 类型：反常识
- 人群：M1 M3
- 痛点：P3 + P4
- 机制：否掉所有人都在推荐的选项，再给更具体的替代。反常识 + 可执行 = 高收藏。
- 转化：收藏 + 评论（争论）
- 来源：自有
- 状态：待验证
```

编号格式是 `H-类型-序号`，`类型` 段可以有数字和中文，`H-P1-001`、`H-R-001` 都能解析。缺 `原文` 的条目会跳过。

解析结果进 `hooks` 表，组稿时按人群和痛点精确匹配。人群码和痛点码的定义在 `jiulv/taxonomy.yaml`，默认是这套：

- `M1` 带 0-3 岁婴幼儿，`M2` 带 4-6 岁学龄前，`M3` 带 7-12 岁学龄儿童
- `C1` 情侣／新婚，`C2` 夫妻无孩／度假，`F1` 朋友／闺蜜团
- `P1` 选哪家，`P2` 房型景观与页面不符，`P3` 带娃不方便，`P4` 怕花冤枉钱，`P5` 踩雷与维权风险，`P6` 交通与时间成本，`P7` 人流与预约排队

这套码是默认值。你们团队如果另有一套叫法，改 `taxonomy.yaml` 的 `label` 和 `aliases`，接口和界面都会跟着变。也可以在 config.yaml 里用 `taxonomy: 路径` 指向自己的文件。

## 分块

按 Markdown 标题切段，段落超过 700 字再按句号、感叹号、换行切开，相邻块重叠 80 字。少于 20 字的块丢掉。

检索命中到段落，再聚合成文档返回，所以一个长文档里只有一段相关也能被找到。

## 增量与删除

`jiulv ingest` 先比文件修改时间，没变直接跳过，不重新解析。时间变了才读内容算哈希，哈希也没变就只更新一下记录。

源目录里删掉的文件，下次收录会同步从索引移除（`--no-prune` 可关掉）。移走整个来源不会自动清，需要 `jiulv ingest --rebuild`。

## 不收录什么

默认跳过 `_raw`、`node_modules`、隐藏目录、Office 临时文件（`~$` 开头）。图片和视频不进库，只在正文里保留引用，避免仓库变重。

`.doc`／`.xls` 这种老格式不解析，会尝试当 zip 读一层 xml，失败就跳过并在报告里列出来。
