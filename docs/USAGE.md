# 使用说明

这份文档讲清楚三件事：怎么把它跑起来、界面上每一块是干什么的、写一篇稿子该按什么顺序动。

想把它接到 Claude、Cursor、Codex、DeepSeek 这些模型上，看 [`LLM.md`](LLM.md)。装不上、起不来、乱码这类问题，先看 [`WINDOWS.md`](WINDOWS.md)（Windows）或直接跑 `jiulv doctor`。

新笔记怎么进来、新目录怎么接、改完为什么没反应，看 [`ITERATE.md`](ITERATE.md)。

---

## 一、启动

三种启动方式，日常只需要一种。选双击就不用管命令。

### 双击启动（最省事）

macOS：双击桌面上的 `酒旅知识库.command`。这个文件是安装时放的，里面写死了项目路径。

项目里对应的原件是 `scripts/jiulv-start.command`，双击效果一样。拿到分发包的人，只用双击包根目录的 `01-双击启动.command`；`scripts/` 里那个同名原件包里也带着，是同一份东西，不用管它。

Windows：双击 `scripts/jiulv-start.bat`，分发包里是包根目录的 `01-双击启动.bat`。

双击之后会发生三件事，你什么都不用做：

第一，检查 `.venv` 在不在。不在就建一个。
第二，检查依赖装没装。没装就装，装不上会提示该装什么，不会只甩一段报错。
第三，服务起来之后自动打开浏览器。

如果服务本来就在跑，双击只会把浏览器再打开一次，不会起第二个进程。

### 命令行启动

```bash
cd /path/to/jiulv-kb
.venv/bin/python -m jiulv.cli start
```

Windows 上是：

```
cd /d D:\jiulv-kb
.venv\Scripts\python -m jiulv.cli start
```

加参数可以改行为：

- `--port 8788` 换端口。默认 8787，被别的程序占了会自动往后顺延一个。
- `--no-browser` 不自动开浏览器。开机自启用的就是这个。
- `--no-watch` 只起网页，不跑后台同步。
- `--interval 60` 后台同步的检查间隔，单位秒，默认 120。

有一条要记住：**不要写 `python -m jiulv start`**。包里没有 `__main__.py`，那样写会报错。要写 `python -m jiulv.cli`，或者直接用 `.venv/bin/jiulv`。

### 开机自启

```bash
jiulv autostart on       # 装
jiulv autostart status   # 看装没装、在不在跑
jiulv autostart off      # 卸掉
```

macOS 写 LaunchAgent，Linux 写 systemd 用户服务，Windows 建计划任务。都不需要管理员权限。

自启跑的命令带 `--no-browser`，开机自动弹一堆标签页是骚扰不是便利。日志在 `data/logs/jiulv.log`。

`autostart status` 显示「已安装：是，在运行：否」是正常的：这个字段看的是 launchctl 有没有托管它，而你手动在终端里起的那个进程不归它管。

### 启动之后

浏览器打开 `http://127.0.0.1:8787`。

第一次启动会先建索引，1500 篇大约半分钟到一分钟，控制台会一行行打进度。之后每次启动，没变化的文件直接跳过，两三秒就绪。

控制台会打印探测到几个来源库、各多少篇。看到篇数是 0 就说明路径没连上，跑 `jiulv doctor` 看是哪一条。

### 起不来怎么办

```bash
jiulv doctor
```

它会检查系统、Python 版本、SQLite 版本、控制台中文能力、长路径设置、配置文件、依赖、每个来源在不在、库能不能读。把输出整段贴出来，基本就能定位问题。

只有两种情况会返回非 0：一个来源都没连上，或者库文件存在但读不了。

## 二、界面

三个区：左边筛选，中间内容，右边阅读器（点开一篇才出现）。

顶部是搜索框和六个页签：检索、图谱、组稿台、钩子库、来源、数据。

### 检索页

搜索框里打词就搜。空格分词，多个词之间是 AND 关系，全都不中会自动退回 OR，不会给你一片空白。中文两个字就能搜，不需要凑够三个字。

左边四个筛选块：地区、类型、等级、来源。**点一下直接列文档，不需要先打关键词**。可以叠加，比如先点「云贵川」再点「爆款笔记」，就是云贵川地区的爆款笔记。再点一次取消。

结果按等级排，S 级在最前面。不按时间排，是因为按时间排会把 sleep 日志、校对记录这类杂项顶到最上面。

每张卡片写的是：等级、类型、标题、地区、酒店、赞藏评、以及命中的原文片段。命中词在片段里高亮。

卡片上如果写「另有 2 份副本」，说明同一篇内容在三个来源目录里各有一份，这里只显示了一份。原始文件一个都没动。

底部「继续加载」每次加 30 条。

左侧筛选区底部的「清空筛选」回首页。带关键词时筛选是叠加在检索结果上的，清掉筛选不会清掉关键词。

### 阅读器

点任意一张卡片，右边滑出阅读器。

最上面是标题、等级、类型、地区、酒店、赞藏评。中间是**注解区**，这是这套库最值钱的地方：每篇爆款旁边直接列出「为什么这么写」。

注解分几类，每类前面有标签：

- 必须写的保留意见。写这家的稿子如果不提这一条，就会变成软文。
- 可写的卖点。资料里明确说了好在哪，可以直接用。
- 预订启示。对做代订的实际意义，比如哪种房型该推、哪种该劝退。
- 采集点评。当初收集这份资料的人留下的判断，信息密度最高。
- 数据信号。从赞藏评比例和标题用词算出来的，标着「规则推算」，跟原文摘录分开。

每条注解都带原文引用和来源文件路径，点得回去对账。这是刻意的设计：注解不是生成出来的，是从原文里搬出来的。

注解下面是原文全文，最下面是相关篇目（同酒店优先，其次同地区同类型）。

### 图谱

像 Obsidian 那样的关系图，但节点不只笔记。

八类概念节点：地区、酒店、作者、系列、人群、痛点、钩子、手法，加上笔记节点本身，颜色各不相同。

默认看全景，能看到哪些概念互相连着。点任意节点钻进去，看它的一跳邻居：点「三亚保利瑰丽」，列出所有写过它的笔记；点其中一篇笔记，反向链接会告诉你哪几篇跟它共享了概念、共享了哪几个。

支持拖拽和滚轮缩放。

用法上就两件事：找「还有谁写过这家酒店」，找「这个痛点还有哪些笔记」。它不是搜索，别拿它当检索用。

### 组稿台

这是最常用的一页。填几个字段，点「生成上下文包」，拿到一段可以直接投喂给任何大模型的提示词。

字段怎么填：

酒店。写全名，比如「三亚仁恒皇冠」，不要写「皇冠」。输入时会出候选，从候选里选最准。

地区。海南、云贵川、西安、长白山、新疆、崇礼、东南亚这些。同样有候选。

人群。M1 到 M3 是妈妈带娃的三个阶段，C1、C2 是情侣，F1 是家庭。不确定就留空，留空会给你更泛的参考。

痛点。P1 到 P7，对应七种最常见的决策纠结，比如选房、怕踩坑、预算。留空也行。

钩子类型。反常识、决策瘫痪、代价警示、身份代入、时间窗口、数字具体，六选一。不选默认反常识。

期望动作。收藏、评论、私信咨询、转发。这个会写进提示词的转化要求里。

切入角度。一句话，比如「写给第一次带娃去三亚的人」。这一栏最影响成稿质量，值得多想十秒。

补充事实。你手上另有、库里没有的事实，一行一条。比如「大堂今年三月翻新过」。填了会进提示词，不填也不会凭空编。

点生成之后，右侧出来四块内容：

`prompt` 拼好的完整提示词。一键复制，直接给模型。

`warnings` 资料不足的提醒。**这一块必须看**。最常见的一条是「库里没有这家酒店的直接资料」，出现它就说明这次只有同地区参考，写具体房型和服务一定会失控。看到这条，要么先去补采集，要么只写地区泛内容。

`references` 参考篇目，每篇带入选理由（同酒店、同地区、关键词兜底）和片段。写完可以逐条核对参考对不对。

`coverage` 各类素材命中数量。参考 0 条、钩子 0 条，说明这次包是空的，别硬写。

### 钩子库

所有结构化钩子按类型列出来。每条七个字段：原文、类型、人群、痛点、机制、转化、状态。

写标题和第一句的时候翻这一页。它给的是已经验证过能用的原句，不是让你照着抄，是让你知道这类钩子长什么样。

### 来源

每个连上的资料库：名字、路径、在不在、多少篇、上次扫描时间。右上角有手动同步按钮。

这一页存在的意义是让库不是黑盒。搜不到东西的时候先来这里看：是路径断了，还是那批资料本来就没收录。

### 数据

文档数、段落数、注解数、概念数、类型分布、地区分布、来源分布。

下面还有回填区：发布过的稿子的赞藏评，以及按钩子类型聚合的效果统计。积累几十条之后，这一块会告诉你哪类钩子在你账号上真的有效。

## 三、写一篇稿子的顺序

七步，顺序别乱。每步都写了「界面上怎么做」和「用 Agent 时怎么说」，选一种就行。

### 第 1 步，定任务

先想清楚六件事：哪家酒店、哪个地区、给谁看、戳哪个痛点、用哪类钩子、想让人做什么。

想不清楚就先别动。这一步含糊，后面拼出来的上下文包一定是泛的。

### 第 2 步，拿上下文包

界面上：组稿台，填完点生成。

Agent 里：让它调 `kb_context_pack`。

> 用 kb_context_pack 给三亚仁恒皇冠写一篇给带娃家庭的选房笔记，钩子用反常识，角度是第一次带娃去三亚。

拿到包之后先读 `warnings`。有「没有这家酒店的直接资料」这条，就退回第 1 步换个打法。

### 第 3 步，核事实

写到具体楼层、房型、朝向、接机时长、早餐时间这些，先去库里克一次。

界面上：搜酒店名，翻阅读器里的硬资料。

Agent 里：`kb_search` 或 `kb_get_doc`。

**库里有就写，没有就不写。** 这是这套东西最重要的一条纪律。写错一个房型，评论区会挂你三天，而且挂的是账号信誉。

### 第 4 步，写

把第 2 步拿到的 `prompt` 整段给模型，不要再自己另起一段描述需求。

这一点很多人会做错：一边贴了 prompt，一边又补一句「帮我写得活泼点」。重复的信息会稀释约束，模型会挑它爱听的那条执行。`prompt` 里已经把风格、字数、钩子、必须保留的意见、不能写的红线都写进去了。

### 第 5 步，自查

`prompt` 结尾有一组约束条件。逐条对一遍，比让模型自查靠谱。

重点看三条：有没有编库外的事实、有没有写必须保留的保留意见、钩子是不是真的在第一句。

### 第 6 步，存档

写完把稿子连同「这篇为什么这么写」一起回写进库。

Agent 里：`kb_save`，`note` 一栏写清这篇的判断。

这一步是让库越用越厚的唯一办法。只取不存，半年后库里还是那批老素材，而且你会发现每次都在重复解决同一个问题。

### 第 7 步，回填

发布之后记一笔：赞、藏、评，以及有没有到你自己定的爆款线。

界面上：数据页的回填区。

Agent 里：`kb_feedback`，`hook_type` 一定要填对，填错这一条就废了。

积累几十条之后，「数据」页的按钩子类型统计会告诉你哪类在你账号上真的有效。那时候再回来调第 1 步，就是有依据的调，不是凭感觉。

## 四、命令行

这一节里的 `jiulv` 是简写，指 `.venv/bin/jiulv`。要先激活虚拟环境才有这个命令：

```bash
cd /path/to/jiulv-kb
source .venv/bin/activate      # Windows 是 .venv\Scripts\activate
```

不想激活也行，把 `jiulv` 换成 `.venv/bin/python -m jiulv.cli`，效果一样，Windows 上是 `.venv\Scripts\python -m jiulv.cli`。

命令都支持 `--config <路径>` 指定配置文件，不指定就找当前目录的 `config.yaml`。

### 日常三条

```bash
jiulv start      # 起服务：建索引 + 网页 + 后台同步
jiulv search "三亚 亲子 选房"
jiulv stats      # 库里多少篇、各类型各多少
```

`search` 可以加筛选：`--region 海南`、`--type note`、`--hotel 三亚瑞吉`、`--limit 20`、`--mode keyword`。加 `--json` 出结构化结果，方便脚本接。

### 看来源

```bash
jiulv sources              # 每个来源：在不在、多少篇、上次扫到什么时候
jiulv sources --json       # 给脚本用
```

新笔记进没进来，先跑这条。某个来源篇数不变就是那个目录没扫到。

### 资料相关

```bash
jiulv connect              # 探测本机资料库，写进 sources.yaml
jiulv connect --dry-run    # 只看探测到什么，不写文件
jiulv connect --deep       # 连历史项目库（夹带代码仓库，会慢）
jiulv connect --only wb-library,oc-reference
jiulv sync                 # 增量同步一次，指纹没变就跳过
jiulv sync --source "名字"  # 只同步某一个来源
jiulv sync --force         # 没变化也强制重扫
jiulv watch                # 常驻监听，有变化就收录
jiulv ingest               # 全量扫一遍并建索引
jiulv ingest --rebuild     # 清空重建（会重新算注解和图谱，慢）
jiulv ingest -v            # 逐条打印收录情况，排查「为什么这篇没进来」用
jiulv ingest --refresh-derived   # 文件没变也重算注解和图谱
```

`sync` 和 `ingest` 的区别：`sync` 只看连着的来源，走指纹判断，没变化 0.2 秒就返回，适合频繁跑；`ingest` 是完整一轮扫描，可以用来重建。日常用 `start`，它内部就带着 `sync`。

新增来源、改动配置之后**不用重启服务**，同步线程每轮会重读配置。细节见 `docs/ITERATE.md`。

### 组稿与导出

```bash
jiulv compose --hotel 三亚仁恒皇冠 --region 海南 --persona M2 --pain P2 --hook 反常识
jiulv compose --hotel 三亚瑞吉 --json    # 结构化输出
jiulv tools --format openai              # 导出 function calling 的 schema
jiulv tools --format mcp                 # 导出原始 inputSchema
jiulv export --out data/export           # 导出 docs/hooks 为 jsonl
jiulv where                              # 打印各客户端配置要填的绝对路径
```

`compose` 不填也能出包，只是参考会偏泛。`where` 是给接大模型用的，会直接打印出可以复制的配置片段。

### 服务与自检

```bash
jiulv serve --host 0.0.0.0 --port 8787   # 只起网页，不带后台同步
jiulv start                              # 网页 + 后台同步
jiulv doctor                             # 环境自检
jiulv autostart on|off|status            # 开机自启
jiulv mcp                                # 以 MCP server 方式跑（给客户端调，不是给人用）
```

想让同局域网的其他机器访问，用 `serve --host 0.0.0.0`，同时把 `config.yaml` 里的 `security.api_keys` 配上，把 `allow_localhost_without_key` 关掉。裸着开到公网等于把资料送人。

## 五、资料怎么放

不改目录结构也能用，但改对了检索和组稿会准很多。库靠约定判断类型、地区、等级。

### 目录名带前缀

`13_钩子库`、`04_风格规则`、`07_硬资料`、`02_地区素材库` 这类前缀会被认出来，自动归类到钩子、规则、事实、地区素材。

### 文件名带等级

`S_`、`A_`、`B_` 开头的文件会被记成对应爆款等级。也可以在正文里写「爆款等级：S级」。

S 级在检索排序里加权，在列表里排前面。等级是你自己定的标准，用得越多越准。

### 正文写字段

笔记头部这几行会被抽成结构化字段：

```
- **标题**：三亚瑞吉最全选房指南
- **地区**：海南·三亚·瑞吉
- **互动数据**：46赞 / 20收藏 / 162评论
- **作者**：某某
```

地区那条三段式会自动拆成地区「海南」和酒店「瑞吉」，这是后面组稿能匹配上的关键。

### 钩子按七字段写

钩子文件每条这样写：

```
## H-R-001
- 原文：这家酒店最贵的房型，反而是最不划算的
- 类型：反常识
- 人群：C1
- 痛点：P4
- 机制：违背贵等于好的直觉
- 转化：收藏
- 状态：待验证
```

写对了会进结构化钩子表，组稿时能按人群和痛点精确取。不写就只是一段普通文本。

### 外部整份资料：拆成单篇再放

从豆包、别家知识库、PDF 导出来的东西，往往是一份几万字的大文件，三十个主题挤在一起。**别整篇塞进库里**。

整篇塞的问题：搜「魔富士」会命中这份 15K 的大文件，返回的是整篇，切片切不准；侧栏那个地区下只有一篇，看着像没资料。

正确做法是拆成单篇，放在 `data/library/<主题>/` 下，目录名和文件名自己定，一部份一个文件：

```
data/library/
  maldives/
    00-资料说明与配套用法.md
    01-上岛方式-快艇内飞水飞.md
    02-餐型-BB-HB-FB-AI怎么选.md
    16-单岛-魔富士康斯丹.md
    ...
```

然后在 `config.yaml` 里把 `data/library` 加成一个来源，`group` 写 `library`：

```yaml
  - name: 自有资料库
    group: library
    path: data/library
    include: ["**/*.md", "**/*.txt"]
```

这个 group 有两个作用：侧栏「来源」里单独一项「资料库」，卡片标签显示「资料」而不是「爆款笔记」——它是要查证的素材，不是能直接发的稿，别混在一起。

拆的时候每篇开头写 `> 地区：马尔代夫`，地区就定了，不用靠关键词猜。这也是资料和笔记的区别：笔记的地区是推断出来的，资料可以写明白。

`data/library/maldives/` 里现在有 22 篇，是这么拆出来的，可以照着做。

## 六、维护

### 平时不用管

`start` 自带的同步线程每 120 秒扫一次来源库，指纹没变就整轮跳过，开销可以忽略。资料目录里新增、修改、删除文件，两分钟内自动反映到库里。

加新来源、改配置也不用重启，同步线程每轮会重读一次。完整讲法在 [`ITERATE.md`](ITERATE.md)。

### 每周看一眼

```bash
jiulv sources
```

确认每个来源都还在、篇数没有异常归零。路径被移动或改名是最常见的故障。

### 大批量改过文件之后

```bash
jiulv ingest --rebuild
```

`--rebuild` 会清空重建，包括重新算注解和图谱。1500 篇大约一分钟。

### 备份

要备份的只有三样：

`data/kb.sqlite3` 全部内容。

`config.yaml` 和 `sources.yaml` 来源配置。

`data/inbox/` 你自己回写的稿子（这个是普通 md，也在库里，但单独留一份更安心）。

拷走就行，没有别的隐藏状态。

### 换电脑

库**不能**靠拷文件夹迁移。`docs` 表里存的是绝对路径，换了目录之后旧记录会全部判为「文件已消失」然后被清掉。

正确的做法有两种：

一，在新机器上重新 `jiulv connect` 加 `jiulv ingest`，从原始资料重建。只要原始资料跟着走，这条路最干净。

二，先 `jiulv export --out data/export` 导出 jsonl 存档，再在新机器上重建。

### 清空重来

```bash
jiulv ingest --rebuild
```

如果连配置都要重来，删掉 `data/` 和 `sources.yaml`，再 `jiulv init` 和 `jiulv connect`。

## 七、常见问题

**搜不到东西。**
先确认收录了没有：来源页看篇数，或者 `jiulv stats`。篇数是 0 就是路径问题，`jiulv doctor` 看哪条断了。篇数正常但搜不到，换两个字试试，或者用 `jiulv search "关键词" --mode keyword` 强制走关键词，排除语义检索配置问题。

**首页的篇数和点进去的篇数不一样。**
两个数口径不同。前者是收录条数，同一篇笔记被几个来源目录各收一份就会重复计。后者是去掉重复之后的内容数。侧栏和列表用的都是去重口径，所以数字能对上。这两个数会随你新增资料变，以页面显示为准。

**侧栏没有我要的地区。**
地区是靠 `jiulv/extract.py` 里的 `REGION_KEYWORDS` 认的，表里没有的词就落空。加一个地区就是在表里加一条，把该地区的代表地名都列进去（马尔代夫就是这么从「东南亚」里拆出来的）。改完要重建一次索引才生效：`jiulv ingest --rebuild`。

**索引页和日记为什么没有地区。**
有意为之。索引页罗列全库标题，必然提到所有地区；记忆和分身档案是工作记录，正文里提一句马尔代夫不代表它是马代笔记。这类文档不判地区，否则点进「马尔代夫」，头几条是工作日志。

**卡片上写「另有 2 份副本」是什么意思。**
同一篇内容在三个地方各存了一份，这里只显示一份。原始文件没有被删除也没有被移动，只是列表折叠了。要逐条看原始列表，调接口时传 `dedupe=false`。

**改了资料，界面没变。**
等两分钟，后台同步会扫到。等不了就跑 `jiulv sync`。如果连篇数都没变，`jiulv sources` 看那个来源的篇数，再确认文件是不是放在了没连上的目录里。详细排查见 [`ITERATE.md`](ITERATE.md)。

**端口被占。**
`start` 会自动往后顺延一个端口，控制台会打印实际用的是哪个。想知道 8787 上是谁占着，`lsof -nP -iTCP:8787 -sTCP:LISTEN`。

**能不能多台机器共用一个库。**
不能直接共享文件。SQLite 放在网络盘上会锁坏。要共用就一台机器跑服务，其他机器连它的 HTTP 接口，`serve --host 0.0.0.0` 加配好 `api_keys`。

**会不会改我的原文件。**
不会。全部只读。所有写入都在 `data/kb.sqlite3` 和 `data/inbox/` 里，`config.yaml` 只在 `init` 时写，`sources.yaml` 只在 `connect` 时写。

**注解是模型生成的吗。**
不是。注解全部从原文小节和采集记录里抽出来，原样搬运。只有一类标着「规则推算」的，是从赞藏评比例和标题用词按固定规则算出来的，跟原文摘录严格分开标注。

**能不能只用命令行不用网页。**
能。`jiulv search`、`jiulv compose`、`jiulv stats` 加 `--json`，足够拼出任何脚本流程。网页只是把这些命令可视化了一遍。

**写稿时模型编了库里没有的东西。**
这是提示词纪律问题，不是库的问题。第 4 步要整段用 `compose` 返回的 prompt，别自己另加需求；第 5 步要逐条核对约束。库里没有的，宁可写少。
